**Audit date:** 2026-11-09  
**Baseline:** `baobab-platform/baobab-cms` default branch before the ADR-specific implementation PRs.  
**Authority:** ADR documents in `docs/adr/` and applicable Shared/CP/IAM contracts.

collections, access controls, canonical mapping and content resolution, editorial publication
hooks, event/outbox, media policy, database migrations, CI and operational runbooks.

## Governance and evidence rules

1. A PR is a **bounded correction**, not approval to mark the entire ADR *Implemented*.
2. Keep each ADR on its own branch and PR. Do not merge until its current head is reviewed and all required checks pass.
3. **#69 remains draft** until ADR-0021 is accepted or amended by the architecture authority.
4. `main` currently has nine timestamped migrations, not just the initial schema. Reconcile older
   implementation documentation against actual migrations, latest contracts and real evidence.
5. Local component fixtures, mocked integrations, green unit tests and a successful image build
   must not be counted as live IAM/CP authority, provider admission, real RabbitMQ delivery,
   independent tenant isolation, or production-ready deployment.
6. When a new dependency/security issue is shared by all branches, fix it at the authoritative
   runtime/security layer rather than copy an unrelated change to all ADR branches.

## Connected qualification checklist

- Provision two legal-entity tenants with CP-issued scope; prove one tenant can never read,
  update, publish, or export the other's CMS content, metadata, mappings or media.
- Publish a real CMS-owned record and verify the original PostgreSQL transaction commits its
  content and durable canonical event together; simulate failed outbox insert and lost response.
- Publish from actual RabbitMQ to a real consumer with retries, crash/replay, idempotent effect
  and independent export of trace/correlation identity.
- Exercise IAM workforce token issuance, binding revocation, suspended tenant, unknown market,
  absent estate grant and expired membership in real connected endpoints.
- Validate CP canonical identity mappings for ProductContent vs Medusa authoritative commerce
  state, including changed SKU, stale mapping and cross-market variants.
- Prove signed private asset delivery, quarantine denial, expired rights, orphan scanning,
  binary restoration and tenant-specific storage controls.
- Run data-bearing PostgreSQL 17 migration and rollback/forward-fix rehearsals, then restore
  both metadata and binary assets, verifying canonical IDs and outbox state.
- Verify independently published digital estate snapshots/SSR requests and cache invalidation,
  never asserting a real estate revalidation from a fixture alone.

**Final classification:** Partial implementation across the ADR family; material isolation,
security and correctness defects corrected in PRs. Connected operational acceptance is
**not established** by this audit.
